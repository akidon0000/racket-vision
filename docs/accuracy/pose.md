# 選手の骨格と特定の精度

- 読み手: 選手の検出（`PlayerPose`）を直す人（エージェントを含む）
- 目的: コートにいる選手をどれだけ見つけ、同じ人に同じ番号を付け続けられているか、何を直して何が残っているかを残す。直したら、下の「記録」に追記する

## 結論（2026-11-16）

ダブルスの 4 人を、骨格つきで見つけ、それぞれに番号（手前 0・1、奥 2・3）を付け続けられるようになった。番号は、同じ選手には同じ色で描く。

| 動画 | 4 人そろったフレーム | 2 人以上 | 追跡の数 | 目視 |
| --- | --- | --- | --- | --- |
| 1min-01（高い位置から） | 74% | 100% | 5 | 60 秒間、4 人とも同じ番号のまま |
| 1min-12（体育館、縦長） | 66% | 99% | 4 | 4 人とも同じ番号のまま |
| 1min-10（屋外、縦長、コートなし） | 75% | 99% | 5 | 未確認 |
| 1min-04（ベースラインの後ろから） | 58% | 81% | 22 | 1 つの場面の中では同じ番号。場面が切り替わると付け直す |

「追跡の数」は、選手を追い始めた回数。4 人を最初から最後まで追えれば 4 になる。

## 仕組み

| 段 | 処理 | ファイル |
| --- | --- | --- |
| 1. 範囲 | Vision の骨格検出は、映像を小さくしてから見るので、遠くの選手を落とす。範囲を絞ってかける。コートがあれば、奥の半面と手前の半面（横に長ければ左右に分ける）。無ければ、画面を格子に分ける。追えている選手は、そのまわり（選手の約 3 倍の正方形）だけを見る。広く探すのは、選手が足りないときと 0.5 秒ごと | `PoseRegions.swift`、`CourtPlayerDetector.swift` |
| 2. 骨格 | `VNDetectHumanBodyPoseRequest`。関節 5 つ以上の人だけを残す。体から大きく外れた関節を外す。重なる範囲から同じ人が 2 回出たら、関節の位置で 1 つにまとめる | `VisionBodyPoseDetector.swift`、`PoseDeduplicator.swift` |
| 3. 選手の候補 | 足元（両足首の中点）をコートの面へ写し、コートの外 2 m（横）・2.5 m（縦）まで、または映像の上でコートの矩形から身長の 0.6 倍までを選手の候補にする。その場所に立つ人の身長の見込みの 0.3〜2 倍の大きさに限る（観客の上半身を外す） | `PlayerCandidate.swift`、`CourtPlane.swift` |
| 4. 追跡 | 前のフレームの選手と、足元の近さと服の色（胴と腿の平均の色）でつなぐ。手前と奥は入れ替えない。0.2 秒続いたら出す。見つからなくなっても 0.5 秒は前の骨格を出し、1 秒で番号を空ける | `CourtPlayerTracker.swift`、`PoseAppearance.swift` |
| 5. 取り違えの直し | 同じ側の 2 人について、番号を入れ替えたほうが服の色が合う状態が 3 フレーム続いたら、番号を戻す。番号ごとの服の色は、ゆっくり覚え直す | `CourtPlayerTracker.swift` |
| 6. 取りこぼしの探し直し | 追っている選手が見つからなかったら、そのまわりを広さ（2 倍、4 倍）を変えてもう一度探す。Vision は、範囲の中の人の大きさで見つけやすさが変わる | `CourtPlayerTracker.missingRegions` |

測り直す手順:

```bash
COURT_DEMO_DIR=$PWD/DemoApp/videos POSE_COURT_CACHE=<コートの矩形を残すフォルダ> POSE_REPORT_DIR=<書き出す先> \
  xcrun swift test -c release -Xswiftc -enable-testing --filter reportsPlayersOnDemoVideos
```

1 秒に 10 枚かける（`POSE_RATE` で変える）。`POSE_COURT_CACHE` は、球の追跡の `BALL_COURT_CACHE` と同じ形なので、同じフォルダを使える。全 13 本で約 7 分。`POSE_RENDER_VIDEO=1` で、骨格を描いた動画も書く。

Mac でデモを動かすとき: Apple シリコンの Mac では、iOS のアプリをそのまま動かせる（Designed for iPad）。シミュレーターと違って、Vision の検出がその場で動く見込みがある（2026-11-16 時点で、起動までは確かめた。検出が動くかは未確認）。

```bash
xcodebuild -project DemoApp/App/CourtDemo.xcodeproj -scheme CourtDemo \
  -destination "platform=macOS,arch=arm64,variant=Designed for iPad" -derivedDataPath <ビルドの置き場> \
  -allowProvisioningUpdates CODE_SIGNING_ALLOWED=YES CODE_SIGN_STYLE=Automatic DEVELOPMENT_TEAM=<チーム ID> build
```

できた `Debug-iphoneos/CourtDemo.app` は、そのままでは開けない（「実行ファイルの形式が正しくない」）。インストールされた iOS のアプリと同じ形に包むと開ける: `<置き場>/CourtDemo.app/Wrapper/CourtDemo.app` に入れ、`<置き場>/CourtDemo.app/WrappedBundle` を `Wrapper/CourtDemo.app` への記号リンクにして、`open -n <置き場>/CourtDemo.app --args -autoplay 1min-01`。

シミュレーターでデモを見るとき: シミュレーターでは Vision の骨格検出が動かないので、デモのアプリは、macOS で前もって求めた記録を、再生の時刻に合わせて出す（画面に「選手 N 人（記録）」と出る）。記録は、上の手順で書き出した `<動画>.json` を、`DemoApp/videos/<動画>.players.json` として動画の隣に置き、`xcodegen generate` でアプリに入れる（`DemoApp/videos` は git の対象外）。その場の検出が動く実機では、記録は使わない。

「4 人そろった」は、そのフレームで骨格が見つかった選手だけを数えた（前の骨格をそのまま出した選手は数えない）。「追跡の数（前）」は、最初の版の数え方（前のフレームにいなかった番号が出た回数）なので、後の値より大きく出る。

効いた直し（効いた順）:

| 直し | 効き目 |
| --- | --- |
| 追えている選手のまわりを、選手の約 3 倍の範囲で見る | 範囲が狭すぎる（選手の 1.8 倍）と、Vision は人を見つけない。1min-01 の奥の選手で、150 px 四方では 0 人、300 px 四方では見つかった。4 人そろう割合が 31% から 63% に上がった（01） |
| コートが無いときは、画面を格子に分けてかける | 10 と 11 で、4 人そろう割合が 0〜4% から 50% 前後に上がった |
| 重なる範囲の骨格を、枠の重なりではなく関節の位置でまとめる | 手前の大きな選手の枠に入った奥の選手を、同じ人として捨てていた。13 の追跡の数が 196 から 24 に減った |
| 服の色でつなぎ、取り違えを戻す | 01 の奥の 2 人が、すれ違いで番号が入れ替わり、そのままになっていた。直した後は 60 秒間同じ番号 |
| 四隅が映像から 2 割以上外れたコートは使わない | 12 は、コートの検出が手前の角を画面のはるか外に出していて、本物の選手を捨てていた。0% から 66% |
| コートの外の判定を、映像の上の距離でも見る | 04 は、カメラが低く、奥の選手の足元の数画素のずれが数 m になって、奥の選手を捨てていた |

試して採らなかったもの:

| 試したこと | 結果 |
| --- | --- |
| Vision の人の枠の検出（`VNDetectHumanRectanglesRequest`）で選手を探してから骨格をかける | 01・04・12 で、1 人も見つからなかった（選手が小さすぎる） |
| 番号ごとの服の色を、見つけるたびに置き換える | 取り違えた相手の色にすぐ染まって、取り違えを戻せなかった。ゆっくり覚え直すようにした |

## 確かめていないこと・分かっている限界

- 関節の位置の正しさ（PCK）は、正解のラベルが無いので測っていない。目で見て、選手に骨格が重なっているかだけを見た。
- 番号の正しさは、01 と 12 しか通して見ていない。05 では、10 秒と 20 秒で手前の 2 人の色が左右で入れ替わっていた。選手が位置を入れ替えたのか、取り違えたのかは確かめていない。
- 放送映像の場面の切り替え（04、05、08）では、番号を付け直す。前の場面の選手と同じ番号になるとは限らない。
- シングルス（06）でも、上限は 4 人。審判や球拾いを選手に入れることがある。`CourtPlayerDetector(maximumPlayers: 2)` で 2 人にできる。
- iOS のシミュレーター（iPhone 17、Xcode 27.1）では、Vision の機械学習の検出がどれも動かない。骨格（"Unable to setup request in VNDetectHumanBodyPoseRequest"、revision 1 も同じ）、人の枠（"Could not create inference context"）、新しい API の `DetectHumanBodyPoseRequest`（"No available compute device for VNComputeStageMain"）を試した。計算装置を CPU に指定しても動かなかった。デモの画面では「選手 検出不可」と出て、骨格は描かれない。実機では動く（下）。
- 処理時間は、macOS（Release）で 1 フレーム 35〜80 ms。実機（iPhone 17 Pro、iOS 27.3、デモの Debug ビルド）では、1min-01 で 1 回 28〜85 ms（最初の 1 回は 196 ms）。デモは 0.1 秒ごとにかける。
- 実機では、1min-01 の最初の 28 秒で、1 秒ごとのログのうち 25 回が 4 人、2 回が 3 人だった（番号は 0〜3 のまま）。骨格が選手に重なって描かれることは、実機の画面でユーザーが確かめた（2026-11-16）。
