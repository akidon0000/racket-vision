# wiki-* の執筆

今の手順と正本を、ジャンルごとの `wiki-*` スキルに書く。判断の理由は wiki に書かず、[write-adr](../write-adr/SKILL.md) で ADR にする。

## 範囲

- wiki-* スキルの節の新規作成と更新。
- 各 wiki-* スキルの説明文（description）の更新。
- 判断の理由と経緯は [write-adr](../write-adr/SKILL.md) で ADR に書き、wiki-* からはそのリンクを張る。
- 精度の測り方は [improve-vision-accuracy](../improve-vision-accuracy/SKILL.md)、動画の切り出し方は [clip-play-videos](../clip-play-videos/SKILL.md) が正本なので、wiki-* に同じ手順を書かない。

## ジャンル

| スキル | 書くこと |
|---|---|
| `wiki-git` | ブランチ、コミット、PR の決まり、コミットの前に流す検証、PR の証跡 |
| `wiki-repo` | リポジトリの構成、フォルダの名前、記録の基準、スキルの足し方、要確認 |

## 進め方

### 1. 既存の節を確かめる

`wiki-*` の中身を読み、同じ内容の節があるか確かめる。あれば新しい節は作らず、その節を直す。

### 2. 事実を確かめてから書く

- コマンドは実行して、結果を確かめる。実行できないもの（実機が要るなど）は、その旨を書く。
- ファイルのパスは、存在を確かめてから書く。
- 数字や名前は、確かめた値だけを書く。

### 3. 節の形にする

各節の冒頭に、読み手と目的を書く。

```markdown
## <タイトル>

- 読み手: <誰が読むか>
- 目的: <このページで分かること>
```

続けて、手順やコマンドを書く。コマンドは `bash` のコードブロックに入れる。見出しと箇条書きを中心にし、文は短くする。本文は常体で書く。

### 4. ジャンルに足す

新しい節は、該当するジャンルの `wiki-*` スキルに足す。ジャンルに合わない手順（例: 実機へのインストール）は、新しい wiki-* を作る前に ADR で決める。それまでは `CLAUDE.md` に短く置く。

### 5. 確かめられないものは要確認へ

確かめられない手順や迷う記述は、`wiki-repo` スキルの「要確認」の節に 1 件 1 行で書く。wiki-* の節には、確かめた手順だけを置く。

### 6. 展開する

`apm install` で展開し直す（`wiki-repo` の「スキルを足す・変える」）。

## チェック

- [ ] 冒頭に読み手と目的がある
- [ ] コマンドとパスを確かめた（確かめられなかったものは要確認へ）
- [ ] 該当するジャンルの wiki-* に入っている
- [ ] 判断の理由は ADR へのリンクにしてある
- [ ] 常体で、日本語で書いている
