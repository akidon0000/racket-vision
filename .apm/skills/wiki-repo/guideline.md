# スキルの接頭辞と呼ばれ方

- 読み手: スキルを足す・名前を変える人、エージェントセッション
- 目的: `wiki-` と `auto-` などの違いと、新しいスキルにどの名前を付けるかを示す

## 結論

- **`wiki-*`**: 今の手順を書いた参照。作業者が必要なときに読む。「どうやるか」の決まりを書く。
- **`auto-*`**: 作業の途中で他のスキルが呼ぶ処理。利用者は直接呼ばない。「何をどの順で実行するか」を書く。

## 比較

| | `wiki-*` | `auto-*` |
|---|---|---|
| 役割 | 手順を読むための参照 | 手順を実行する処理 |
| 誰が使うか | 作業者（エージェント）が、作業に合うときに読む | 他のスキルの途中で呼ばれる |
| 利用者が直接呼ぶか | 通常は呼ばない。頼めば読める | 呼ばない |
| 中身 | 決まり、コマンド、要確認 | 実行の順番、判断、他のスキルの呼び出し |
| 例 | `wiki-git`（ブランチ、コミット、PR の決まり） | `auto-create-pr`（コミット、push、PR の作成） |
| 手順が変わったとき | 決まりを書き換える | 実行の順番を書き換える |

## 他の付け方

| 名前 | 意味 | 例 |
|---|---|---|
| 接頭辞なし（作業の名前） | 利用者が頼む作業 | `improve-vision-accuracy`、`clip-play-videos` |
| `write-` | 文書を書く。直接頼むことも、他から呼ばれることもある | `write-adr`、`write-wiki` |

## 迷ったとき

1. 読めば手順が分かるものは、`wiki-`。
2. 他の作業の途中で勝手に動くものは、`auto-`。
3. 利用者が頼む作業は、接頭辞なし。
4. 文書を書くものは、`write-`。

## 同じ手順を両方に書かない

`wiki-` は決まりを書き、`auto-` は実行の順番を書く。同じ手順を両方に書くと、片方だけ古くなる。見つけたら、書く内容が多いほうに寄せ、もう片方は参照にする。

例: PR のタイトルと本文の決まり、コミットの前に流す検証は `wiki-git` に書く。コミットして push し、`gh pr create` を呼ぶ順番は `auto-create-pr` に書く。`auto-create-pr` は、決まりを `wiki-git` から読む。
