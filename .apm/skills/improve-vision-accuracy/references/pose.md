# 骨格分析

選手の骨格（関節の位置）を推定し、コートにいる選手を特定する機能（`PlayerPose`）の精度を測って直すときに読む。

2026-11-16 時点の状態: `CourtPlayerDetector`（Vision の骨格検出を範囲を絞ってかけ、選手を選んで追う）と、測る仕組み `reportsPlayersOnDemoVideos`（`Tests/PlayerPoseTests/DemoVideoPlayerReportTests.swift`）がある。測り方と結果は [Docs/accuracy/pose.md](../../../Docs/accuracy/pose.md)。関節の正解（下の表の `Tests/PoseAnnotations`）と PCK は、まだ無い。

以下は、最初に書いた計画。

## 作るもの

コートの検出で役に立った形を、そのまま写す。

| コートの検出にあるもの | 骨格分析で作るもの |
| --- | --- |
| `CourtRectangleDetector`（方式ごとに同じ入出力） | 方式ごとに同じ入出力の protocol。返すのは、人ごとの関節の位置と確からしさ |
| `CourtDetectionMethod` と開発パネルのスイッチ | 方式の列挙と、開発パネルで出し分けるスイッチ |
| `Tests/CourtAnnotations/<動画>.json`（交点 12 個） | 関節の正解（フレームごとに、人ごとの関節の位置。見えない関節は入れない） |
| `exportsQuadsOnDemoVideos`（2 秒ごとの書き出し） | 関節の書き出し。`compare_exports.py` が読めるよう、`video`、`seconds`、`imageWidth`、`imageHeight` を同じ名前で持つ |
| `reportsDetectionOnDemoVideos`（結果を描いた画像） | 関節と骨を描いた画像 |
| `previewsLineModelSearch`（途中の段の画像） | 方式の途中の段（人の枠、関節の候補など）の画像 |

`compare_exports.py` は四角形の四隅を前提にしている。骨格を足すときは、関節用の集計を足すか、別のスクリプトにする。

## 測るもの

| 指標 | 中身 | 理由 |
| --- | --- | --- |
| PCK | 関節の位置のずれが、人の大きさ（胴の長さなど）の一定の割合以内に入った関節の割合 | 画面の中の人の大きさが動画ごとに大きく違うので、px のずれでは比べられない |
| 見逃し・誤り | 映っている人を出さなかった数、人のいない場所に出した数 | コートの検出と同じく、「何か返した」割合だけでは誤りが隠れる |
| 揺れ | 止まっている人の関節が、フレームの間でどれだけ動くか | 動作の分析では、フレームごとの正しさより、続けて見たときの安定が効く |
| 処理時間 | Release ビルドの 1 フレームあたり | 録画中に動かすため |

## 気をつけること

- サンプル動画のほとんどは放送映像で、選手が小さく、重なり、後ろ向きのことが多い。ショート動画は選手が大きく映るが、手持ちで揺れる。両方で測る。
- 観客や審判も人として出る。コートの中の人だけを対象にするなら、コートの検出の結果（コートの面への変換）で足元がコートの中かを確かめられる。
- 最初の方式は、Vision の `VNDetectHumanBodyPoseRequest` を基準に置くとよい。追加の依存が無く、比べる相手になる。
