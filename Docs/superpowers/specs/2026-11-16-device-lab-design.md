# 機種ごとの再現（`DeviceLab`）と、3D のシミュレーションの設計

- 読み手: `DeviceLab` と 3D のシミュレーションを実装する人（エージェントを含む）と、実装の前に中身を確かめる人
- 目的: 次の 2 つについて、何を作り、何を作らず、どう確かめるかを決める
  - iPhone の機種と OS を指定して、その機種でデモを動かしたときの結果を Mac で再現する仕組み（`DeviceLab`）
  - デモの下の段（シミュレーション）を 3D で描き、ドラッグで視点をコートの中心のまわりに回せるようにする

## 位置づけ

iOS のシミュレーターでは Vision の機械学習が動かない（`Docs/accuracy/pose.md`）。実機は手元の 1 台（iPhone 17 Pro）しかない。そこで、Mac の上で、機種ごとの条件を指定してデモと同じ処理を流し、機種による結果の違いを確かめられるようにする。

2026-11-16 に Mac（M4 Max、macOS 26.7）で調べた結果、Vision の骨格の検出の結果そのものは、計算装置でほとんど変わらなかった。

| 計算装置 | 1 回の時間 | CPU との関節の位置の差（最大） |
| --- | --- | --- |
| ニューラルエンジン | 8 ms | 0.0003（1920 px で 1 px 未満） |
| GPU | 6 ms | 0.0003 |
| CPU | 45 ms | — |

使える検出の版は 1 つ（revision 1）だけだった。機種で結果が変わるのは、計算の中身ではなく、1 回の検出にかかる時間と、それによって間に合わずに飛ばすフレームである。そこで、`DeviceLab` は「機種ごとの時間と入力の条件で、どのフレームが処理され、どの結果が画面に出るか」を再現する。

## 再現するもの・しないもの

| 機種で変わるもの | 再現 | やり方 |
| --- | --- | --- |
| 検出 1 回の時間（コート、球、骨格） | する | 機種ごとの時間を持ち、仮の時計で、検出中に来たフレームを飛ばす（デモのアプリと同じ決まり） |
| 画面に出るまでの遅れ | する | 検出を始めたフレームの時刻に、その機種の時間を足した時刻に、結果を画面に出す |
| 映像の解像度とコマ数 | する | 機種の上限まで映像を縮め、コマを間引いてから流す |
| 熱で遅くなる | する（簡単な形） | 経過時間に応じて、検出の時間を一定の割合で延ばす |
| 使える API（OS） | する（切り替えだけ） | 機種の OS で使えない機能は使わない。例: 骨格の検出は iOS 14 から |
| Vision の古い版の結果 | しない | Mac で動くのは Mac の Vision。古い iOS の Vision は動かせない |
| 特定の機種のニューラルエンジンの計算 | しない | 調べた範囲で、計算装置による差は 1 px 未満 |
| カメラの写り（レンズ、手ぶれ補正、色） | しない | 動画ファイルを入力にするので、写りは動画のまま |

## 作るもの

### 画面

macOS のアプリ。今のデモ（縦画面）と同じく、上に動画、下に白い背景のコートの線・選手の骨格・球の軌跡を描く。これを機種ごとに 1 列とし、2 機種まで横に並べて比べる。

| 部分 | 中身 |
| --- | --- |
| 上の帯 | 動画の選択、機種の選択（列ごと）、再生・一時停止・コマ送り、再生の速さ |
| 列 | 上に動画（その機種の解像度に縮めたもの）、下に 3D のシミュレーション（下の「3D のシミュレーション」）。列の下に、その機種での数（処理したフレームの割合、検出 1 回の時間、選手 4 人がそろった割合、球を出したフレームの割合） |
| 機種の一覧 | 機種ごとの条件を表で見る。値が実機で測ったものか、見込みかを出す |

再生は、実時間ではなく、仮の時計で進める。Mac の速さに関係なく、指定した機種の条件で、どのフレームが処理されるかが決まる。結果は、全フレームを先に求めておき（1 動画・1 機種で数十秒）、再生はそれを時刻で引いて描く。コマ送りで同じ結果が何度でも出る。

### 機種の条件（`DeviceProfile`）

| 項目 | 例（iPhone 17 Pro） | 出どころ |
| --- | --- | --- |
| 名前、機種の番号 | iPhone 17 Pro、iPhone18,1 | — |
| OS | iOS 27.3 | — |
| 検出 1 回の時間（ms） | コート 30、球 4、骨格 50 | 実機のデモで測る |
| 時間のばらつき | 骨格 28〜85 | 実機のデモで測る |
| 映像の上限 | 3840×2160、60 コマ/秒 | 機種の仕様 |
| 熱で遅くなる割合 | 10 分で 1.2 倍 | 見込み |
| 値の出どころ | 測った / 見込み | — |

条件は JSON の一覧（`DeviceProfiles.json`）に持ち、アプリに入れる。最初に入れるのは、測った iPhone 17 Pro と、見込みの数機種（iPhone 15、SE（第 3 世代）など）。見込みの値は、公開されている性能の比から決め、画面に「見込み」と出す。実機で測ったら、値を置き換える。

### 実機で測る

デモのアプリに、検出 1 回の時間をコート・球・骨格ごとにためて、動画の終わりにログへ出す機能を足す（今は骨格だけを 1 秒ごとに出している）。ログの形は `DeviceProfiles.json` にそのまま写せる形にする。

### 処理の流れ（`DeviceRun`）

1. 動画を先頭から読み、機種の上限まで縮め、コマを間引く。
2. フレームごとに、仮の時計で、コート（0.2 秒ごと）・球（毎フレーム）・骨格（0.1 秒ごと）の検出を、前の検出が終わっていればかける。デモのアプリ（`PlayerModel`）と同じ決まり。
3. 検出は Mac で本当に動かす（`CourtFit`、`BallTracking`、`PlayerPose`）。終わる時刻は、Mac でかかった時間ではなく、機種の時間で決める。
4. 終わった時刻に、結果を画面の状態（コート、球の軌跡、選手）に反映する。フレームごとの画面の状態を、時刻の順にためる。

検出器の中の追跡（球の軌跡、選手の番号）も、処理したフレームだけを見るので、飛ばしたフレームの分だけ、実機と同じように粗くなる。

## 3D のシミュレーション

デモ（iPhone）と `DeviceLab`（Mac）の下の段を、3D で描く。白い背景に、コート（線とネット）、選手の骨格、球を置く。ドラッグで、視点をコートの中心のまわりに回す（上下左右）。2 本指（Mac ではスクロール）で近づく・離れる。最初の視点は、元の映像のカメラの位置。

### 何を 3D にできるか

映像は 1 台のカメラなので、画面の点からは、カメラからの向きは分かるが、距離は分からない。地面の上にあるもの（コート、選手の足元）は、地面と交わる位置で決まる。高さのあるもの（選手の体、球）は、別の手がかりが要る。

| もの | 置き方 | 正しさ |
| --- | --- | --- |
| コート | 図面（13.41 m × 6.10 m、キッチン 2.13 m、ネットの高さ 0.86 m）をそのまま置く | 正しい |
| カメラ | コートの四隅の写り方（射影変換）から、カメラの位置と向きを求める（`CourtFit` の `CameraEstimate` を、位置と向きまで出すように広げる） | コートの検出が当たっていれば、正しい |
| 選手の足元 | 今の `CourtPlayer.courtPosition`（コートの面の上の位置） | 正しい |
| 選手の骨格 | 足元を通り、元のカメラのほうを向いた縦の面の上に、関節を置く（カメラから関節への向きと、その面が交わる点）。体の厚み（前後）は出ない、平たい人形になる | 元の視点からは正しく見える。真横から見ると平たい |
| 球 | ラリーの軌跡を、打ってから次に打つまでの区間に分け、区間ごとに、地面の上をまっすぐ進み、高さは重力の放物線になる、とみて当てはめる。当てはまらない区間は出さない | 当てはまれば、高さの目安になる。手で確かめるまでは目安 |

選手の体の前後の厚みは、Vision の 3D の骨格（`VNDetectHumanBodyPose3DRequest`）で出せる見込みがある。ただし、画面の中で一番目立つ 1 人にしか使えず、4 人に使うには選手ごとに範囲を切ってかける必要があり、時間がかかる。最初の版では使わず、平たい人形で出す。

### 描き方

RealityKit（`RealityView`）で描き、視点の操作は `realityViewCameraControls(.orbit)` を使う（iOS 18、macOS 15 から）。回す中心は、コートの中心（ネットの真ん中の真下）。

| 置くもの | 形 | 色 |
| --- | --- | --- |
| コートの面と線 | 薄い板と細い棒 | 灰色 |
| ネット | 半透明の板 | 灰色 |
| 選手 | 関節は小さな球、骨は細い円柱 | 選手の番号の色（`PlayerPalette`） |
| 球の軌跡 | 小さな球の並び | ラリーの色（`BallRallyPalette`）、黒い縁の代わりに少し暗い色 |
| 元のカメラ | 小さな四角錐（向きが分かるように） | 黒 |

### 置くための計算（`CourtScene`）

3D の座標への変換は、iOS と macOS の両方で使うので、ルートのパッケージに `CourtScene`（新設のライブラリ）として置く。入力は、コートの四隅、選手、球の軌跡、映像の大きさ。出力は、コートの座標（メートル、原点はコートの中心、y が上）での、カメラの位置と向き、選手の関節の位置、球の位置。描画（RealityKit）は持たない。

## 置き場所

| 置き場所 | 中身 |
| --- | --- |
| `DemoApp/Library` | 重ね描きの部品（`CourtLinesOverlay`、`PlayerSkeletonOverlay`、`BallDotsOverlay`、`fitRect`）を、macOS でもビルドできるようにする。動画の再生（`VideoPlayback`）は iOS のまま |
| `DemoApp/DeviceLab/Package.swift` | 新設。`DeviceSimulation`（機種の条件、仮の時計での処理、`DeviceRun`）と、その単体テスト。macOS |
| `DemoApp/DeviceLab/App/project.yml` | 新設。macOS アプリの殻（xcodegen）。画面は `DeviceSimulation` と重ね描きの部品を使う |
| `DemoApp/DeviceLab/DeviceProfiles.json` | 機種の条件の一覧 |
| `DemoApp/Library/Sources/VideoPlayback/PlayerView.swift` | 検出の時間をためてログに出す。下の段を 3D のシミュレーションに替える |
| `Sources/CourtScene/` | 新設。3D の座標への変換（カメラの位置と向き、選手の関節、球の軌跡の当てはめ） |
| `Sources/CourtFit/CameraEstimate.swift` | カメラの位置と向き（回転と平行移動）も出す |
| `DemoApp/Library/Sources/CourtSceneView/` | 新設。RealityKit で描く部品（iOS と macOS） |

`DeviceLab` は、ルートのパッケージ（ライブラリの本体）には足さない。デモと検証のための道具であり、ライブラリを使う側には要らない。`CourtScene` は、映像の解析の結果をコートの 3D の座標にするもので、ライブラリを使う側にも役に立つので、ルートのパッケージに足す。

## 作らないもの

- カメラの映像（`CameraDetection`）の再現。入力は動画ファイルだけ
- iOS のシミュレーターでの再現（Vision が動かないため）
- 機種ごとの電池の減り、メモリの上限
- 3 機種以上の同時の比較
- 選手の体の前後の厚み（3D の骨格）。最初の版は平たい人形
- 球の回転、球の正確な高さ（当てはめは目安）

## 確かめ方

| 確かめること | やり方 |
| --- | --- |
| 仮の時計の決まりが、デモのアプリと同じ | 単体テスト。検出の時間を決めた偽の検出器を渡し、処理されるフレームと、結果が画面に出る時刻が、決まりどおりになるか |
| 縮めとコマの間引き | 単体テスト。4K・60 コマの入力を、1080p・30 コマの機種で流したときのフレームの数と大きさ |
| iPhone 17 Pro の再現が実機と合う | 1min-01 を、実機のデモと `DeviceLab` の iPhone 17 Pro で流し、選手 4 人がそろった割合と、球を出したフレームの割合を比べる。差が 10 ポイント以内なら合格 |
| 遅い機種で結果が変わる | 見込みの遅い機種（SE など）で、処理したフレームの割合と、選手 4 人がそろった割合が下がることを、数で確かめる |

| カメラの位置と向き | 単体テスト。決めたカメラでコートの四隅を写し、そこから求めたカメラの位置と向きが、元と 1 cm・0.1 度以内で合うか |
| 骨格の置き方 | 単体テスト。決めたカメラで、コートの上に立つ人形の関節を写し、そこから置いた関節が、元の人形の面の上で 1 cm 以内か |
| 球の当てはめ | 単体テスト。放物線を描く球を写し、当てはめた高さが元と 5 cm 以内か。サンプル動画では、ネットを越える球の高さが 0.9〜3 m に入るかを見る |
| 3D の表示と視点の操作 | シミュレーター（記録を使う）と実機で、1min-01 を流し、ドラッグで回せること、元の視点に戻したときに上の動画と重なって見えることを、画面で確かめる |

結果は `Docs/accuracy/device-lab.md` に書く。

## 分かっている限界

- 見込みの機種の値は、実機で測るまで当たっているか分からない。画面と記録に「見込み」と出す。
- Mac で検出を本当に動かすので、Mac の Vision と iOS の Vision の版が違うと、結果が少し違うことがある（調べた範囲では同じ版）。
- 検出の時間を固定の値（とばらつき）で表すので、映像の中身で時間が変わる（人が多いと骨格の検出が遅い）ことは再現しない。
- 3D の選手は平たい人形なので、元の視点から大きく回すと不自然に見える。
- 球の高さは、1 台のカメラでは測れない。重力の放物線を当てはめた目安であり、打った瞬間やバウンドの前後では外れる。
- コートの検出が外れると、カメラの位置と向きも外れ、3D の全体がずれる。

## 作る順

1. `CourtScene`（カメラの位置と向き、骨格の置き方）と単体テスト。球の当てはめは後
2. デモ（iPhone）の下の段を 3D にする（コート、カメラ、選手）。シミュレーターと実機で確かめる
3. 球の当てはめを足す
4. デモに検出の時間のログを足し、実機で iPhone 17 Pro の値を測る
5. `DeviceSimulation`（機種の条件、仮の時計）と単体テスト
6. `DeviceLab`（macOS アプリ）。3D の部品と、2 機種の比較
7. iPhone 17 Pro の再現を、実機と比べる
